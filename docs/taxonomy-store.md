# Portable taxonomy store

install_taxonomy(snapshot, store_dir, *, markdown=False, expected_sha256=None) validates the existing registry schema/content identity and requires released status. It writes exact input bytes to STORE/VERSION.json, preserving all stable IDs, parent IDs, definitions, inclusion/exclusion/boundary rules, status, replacement and version chain fields. Identical existing bytes are accepted; any conflicting version refuses. No scientific labels are changed and no active configuration is rewritten.

CLI adapter run_taxonomy_store_cli(argv), for parent dispatch as taxonomy-store. Direct invocation: python -m millefeuille.cli.taxonomy_store --snapshot RUN/taxonomy.json --store-dir PRIVATE/taxonomies/research --expected-sha256 HEX [--markdown]. JSON receipt includes raw SHA256, logical content identity, version and installed path; exit 0 success, 2 refusal. Existing --taxonomy processing option stays untouched: point it at the installed version file explicitly.

Optional VERSION.md is deterministic, escaped human-readable derivative, never authority. JSON version is authoritative and user-owned, independent of assistant memory or hosting. Single serialized owner writes to a private directory; no hostile concurrent filesystem mutation guarantee. Existing symlink paths refuse, files are exclusive-create mode 0600. A crash during initial create can leave a partial file requiring manual inspection, not silent repair. JSON may exist if optional Markdown creation fails; retry handles exact bytes. Parent owns real snapshot installation, qualification and the optional memory pointer.
