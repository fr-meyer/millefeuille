# Importing existing OpenKB extraction evidence

`millefeuille source-pack import-openkb --pack PACK --pdf PDF --source-sha256 SHA256 --manifest-sha256 SHA256 --evidence-sha256 SHA256 --output NEW_DIRECTORY` explicitly converts saved OpenKB native/Mistral evidence into native extraction sidecars. It calls no provider and never parses the PDF. The PDF and upstream manifest must be independently hash-pinned. Reads reject symlinks, enforce per-file/cumulative bounds, and are rechecked by the native metadata transaction before publication and readback. The destination must not already exist. Windows publication retains the existing fail-closed policy.

`millefeuille source-pack retrieve-imported --output DIRECTORY --page 1 --page 3` returns selected private page text and verifies its stored hashes. This is extraction-level retrieval, not the existing accepted-run `retrieve` command. Do not publish its stdout.

The importer preserves source identity, DOI, page boundaries, raw response digest, requested/returned alias and actual usage. It does not guess an immutable backend version. Provider JSON stays at the original private location. The conversion uses existing extraction writers, whose historical implementation names contain `fixture`; source provenance explicitly says imported OpenKB evidence.

The result is **not** an accepted run or a complete native source pack. `converted-source-manifest.json` is a conversion artifact, not a discoverable manifest: the PDF is not copied to this output. No stage manifest, index status, summary, classification decision, taxonomy assignment, acceptance or provider-execution receipt is fabricated. Existing native acceptance/classification still require their real upstream artifacts and a locked taxonomy. This seam does not provide an automatic classifier.

Unit tests use explicitly synthetic source bytes. Real-document validation and transaction failure-injection evidence must remain private and separately labelled. Successful native metadata writes include exact readback; native failure rollback preserves journals and restores owned prior bytes.

The evidence pin is SHA-256 of UTF-8 canonical JSON (`sort_keys=True`, `separators=(",", ":")`) mapping each pack-relative input path to its byte SHA-256. Inputs are `manifest.json`, `raw/provider-response.json`, and `pages/page-NNNN.md` for every page under each of the selected root, `extractions/native/`, and `extractions/mistral-ocr/`. Pin this inventory from the independently verified private snapshot before importing. It binds content, not a semantic review verdict.

`millefeuille source-pack materialize-imported --imported DIRECTORY --pdf PDF --source-pack-root NEW_ROOT --structure-output NEW_DIRECTORY` creates a canonical PDF-backed native source pack, copies validated extraction sidecars, writes merged-dual route evidence and computes page/heading structure with the existing local structure processor. The selected text is wrapped in explicit `# Page N` headings before structure analysis; the original OpenKB pages are unchanged. The command fails if that paper already exists in the chosen source-pack root and never marks a run accepted. A failed later stage can leave the fresh source pack for review; do not retry against the occupied destination.

This command still does **not** create genuine summaries, paper-card, retrieval index, acceptance summary, taxonomy lock or classifier results. Those stages require actual model outputs, retrieval index, approved taxonomy and their own product stages. A source/route/structure result is not a substitute for an accepted run.

Fresh destinations are acquired in a protected staging namespace, opened and inode-bound there, then published using Linux renameat2(RENAME_NOREPLACE). No mkdir/first-stat acquisition occurs under the attacker-controlled final parent. Subsequent replacement fails the retained-inode checks and metadata transaction. Existing files, directories and symlinks are never adopted or overwritten.

The threat model grants the attacker mutation authority over the final parent only, not the separate acquisition namespace. This may be a different-UID attacker or a capability-confined same-UID actor. Unrestricted same-UID OS access (or root) can reach private process resources and is explicitly outside the guarantee. Filesystem permissions alone do not constrain an unrestricted same-UID adversary. The caller must designate a staging namespace outside the attacker's authority; it cannot lie beneath the final parent. No-follow ancestor checks require root/current-user ownership and no group/other write, except root-owned sticky directories. Mode-0700 private acquisition containers isolate other users. This is a local filesystem contract; mounts/ACLs/capability confinement must preserve the stated authority separation.

Default staging is /tmp. For a different destination filesystem, explicitly pass --protected-staging-root EXISTING_TRUSTED_DIRECTORY (Python protected_staging_root=...). The caller-designated root must already exist, satisfy the ownership/traversal checks, and share the destination filesystem. There is no automatic fallback to the final parent. Missing renameat2, unsupported no-replace flags, cross-device rename, unsafe namespace or EEXIST fail closed before destination adoption. Private uncertain state is retained; only an empty staging container after publication is removed. No configuration is changed.

Materialization computes privately, reserves both final destinations through this primitive, and writes its PDF through the retained descriptor. Text artifacts use identity-bound metadata transactions. Only route-evidence.json markdown_path and computed/summary.json output_dir are remapped after JSON parsing, then JSON-escaped serialization. Markdown and other content are never globally substituted. All published bytes/JSON and known referenced artifacts are read back. Cross-destination publication is not atomic: failure retains owned partial outputs/PDF and recovery journals for explicit review, rather than deleting or retrying over them.
