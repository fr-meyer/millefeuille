# Scientific fidelity evidence (S04)

This additive mode uses the existing production kernel-isolated PDF boundary.
It is opt-in through observe_scientific_source. Default text extraction and all
existing isolation/resource/refusal policies remain unchanged. No provider,
OCR, private input, dependency installation or acceptance promotion is added.

The child reports page rotation/media box, indexed content operators/operands
(including Tm, Tf, Tj, paths and transforms) and font declarations. Opaque or
array operands are null, not guessed. Content parsing is capped at 2048
operators/page, within the original process/read/output limits. Imports are
warmed before filtering; all source parsing remains after filtering.

The independent frozen GOLDENS remain unchanged. Tests add hand-authored
operator locators to compare eight golden facts, using actual production
boundary calls on synthetic PDFs. Receipts include all raw operations so
reviewers can check state/transform context instead of trusting captions.
The comparator reports structural matches only, never scientific acceptance.
The equation remains unresolved: superscript placement and Symbol font code
are evidence, not verified Greek mapping or mathematical meaning. There is no
glyph mapping/math interpretation capability in this patch. General rendering,
forms, arrays, inherited transforms, clipping and arbitrary PDF layout are not
implemented by the comparison contract. Unnormalized operators are not a
rendered geometry guarantee, even for the closed triangle structural match.

Future Linux x86-64 CI must actually decode five fixtures and emit eight
comparisons as kind S04 payloads under MILLEFEUILLE_EVIDENCE_FRAME_V1.
Each bounded payload is framed into short numbered/hash-bound log lines, not
a single 64 KiB stdout line. Shared archive processing requires complete,
externally bound run/attempt/cell/case records and rejects missing/conflicting
frames. Payloads retain the real source hash; the comparator requires an
independently supplied expected PDF hash and coordinate convention.
Windows verifies failclosed behavior instead of claiming extraction. Receipts
carry source PDF SHA, extractor version, page, oracle region, coordinate
convention, operator locators, actual values and comparison provenance.
No local runtime execution was authorized or performed for this patch.
S04 remains needs-review, not accepted, pending exact-source runtime receipts
and independent review; equation semantic evidence remains missing afterward.

Fractional PyPDF2 FloatObject operands are converted explicitly, not silently
replaced with null. Nonfinite or magnitude-over-1e12 numeric observations
refuse scientific mode; default text decoding is not changed. Added tests
cover real fractional matrices/paths/width, operation/output/input exhaustion,
default-vs-scientific equivalence and a pure scalar nonfinite conversion unit.
These tests are authored but have not yet executed locally or in CI.

S04 top-level source_sha256 is the exact six-entry source map declared in
S04_SOURCE_PATHS in tests/test_scientific_fidelity.py, externally pinned by the
archive manifest. The actual PDF hash remains in observation.source_sha256 and
each comparison, bound to an independently authored expected source hash.
Runtime identity is top-level runtime, alongside the exact fixture case_id.
