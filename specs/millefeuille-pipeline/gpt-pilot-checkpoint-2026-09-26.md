## Read-only published input handoff

`plan_published_gpt_summary_handoff` accepts the expected publication identity
from a trusted commit record. It rechecks the prepared request manifest,
matching source-pack PDF/item/attachment identity, all published snapshots and
summary/provenance/usage bytes, exact file coverage, and the receipt-bound
bundle digest. It returns only source-pack and run-relative artifact refs
plus commit metadata. It makes no provider calls or writes and grants no
acceptance, card-generation, indexing, classification, or write authority.

The real Picard read-only check passed with ten summary refs, ten provenance
records and two source snapshots, using the root approval and published audit
identity. The GCP suite passed 726 tests with 13 expected skips; focused cases
reject corrupted bytes, missing or extra files, symlinks, wrong source-pack
identity, changed preparation and wrong commit metadata. This handoff currently
supports single-source packs. MF-114 multi-source propagation remains open.
